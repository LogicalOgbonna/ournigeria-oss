I see the issue. When a user is banned, the `banned` field on the `User` model is set to `true`. 

However, in `apps/api/src/telegram/telegram.service.ts`, the `handleMessage` and `handleCallbackQuery` functions do not check this `banned` field. 

Here is what happens currently:
1. A message comes in from Telegram.
2. `findOrCreateUser` is called. It looks up the user by `telegramId`.
3. It returns the user object (which only contains `{ id: string }` because of the `select: { id: true }` in the query).
4. The service then proceeds to update `lastSeenAt`, handle commands, or call `processUserMessage` to talk to the AI agent.

At no point does the Telegram service check if `user.banned === true`.

To fix this, we would need to:
1. Update `findOrCreateUser` to also select the `banned` and `banReason` fields: `select: { id: true, banned: true, banReason: true }`.
2. In `handleMessage` and `handleCallbackQuery`, check if `user.banned` is true.
3. If true, send a message back saying they are banned (optionally including the reason) and `return` early so the message isn't processed by the AI.
