## Vision

### 10x Check
The 10x version isn't "a bot that posts tweets." It's **OurNigeria as Nigeria's real-time
civic intelligence voice across every platform where citizens are.**

Current reality: 708K+ budget document embeddings + a knowledge graph sit behind a chat UI.
Citizens must come to you and know what to ask.

10x version: The data comes to the citizens — on the platform they're already on, in the
moment they're already angry. When #EndBadGovernance trends, the agent is already generating
a thread with specific numbers. When a governor announces a project on Twitter, the agent
surfaces the actual budget allocation vs spending.

The feeling: **"OurNigeria always has the receipts."**

### Platonic Ideal
A **civic media nerve center**: The social intelligence platform listens across platforms,
generates data-driven content in the right format for each platform, auto-publishes original
posts, and queues reply candidates for human approval. A dashboard shows trending topics,
drafted content, engagement analytics, and the reply approval queue. Journalists use it as
a source. Citizens tag @awanigeria. The agent gets smarter over time by learning which
content drives the most engagement.

## Implementation Approach
**Standalone NestJS service** (`apps/socials/`) powered by Claude Agent SDK
(`claude_agent_sdk` for Python or `@anthropic-ai/sdk` with agentic tool-use patterns for JS/TS).
This is NOT Mastra — it uses Anthropic's native SDK for building autonomous agents with
tool use. The social agent runs independently from the API's Mastra-based chat agents.
It uses the same underlying data (Neo4j, PostgreSQL) but has its own agent orchestration
loop optimized for social media workflows (listen → decide → generate → publish).

**SDK Implementation Note:** If using JS/TS (to match the NestJS service), the agent loop
is: create message with tools → receive tool_use response → execute tool → feed result back
→ repeat until agent returns text. This is the standard agentic pattern with `@anthropic-ai/sdk`.
If a dedicated JS Agent SDK is released before implementation, use that instead.

Multi-platform architecture with adapter pattern — Twitter first, TikTok/Instagram/WhatsApp
adapters later.

### Keyword Strategy
The listener uses **3 rotating keyword query groups** per poll cycle (to stay within
X API Basic read limits). Queries are configurable via a `social_keywords` system setting
(same pattern as RAG settings in the existing SystemSetting table).

**Default keyword groups:**
| Group | Keywords | Domain Match |
|---|---|---|
| A: Budget/Spending | "Nigeria budget", "government spending Nigeria", state names + "budget" | budget, faac |
| B: Corruption/EFCC | "EFCC", "corruption Nigeria", governor names + "arrested"/"charged" | corruption |
| C: Services/Impact | "NEPA", "light Nigeria", "road Nigeria", "school Nigeria", sector keywords | budget (impact framing) |

**Rotation:** Each poll picks one group. Over 3 cycles (60 min at 20-min interval), all groups are covered. This keeps reads to ~1 query/poll = ~2,160 reads/mo.

**Trend detection via search volume:** The Trends API (`GET /trends/place`) is NOT available
on Basic tier. Instead, detect trending topics by monitoring search result volume changes:
if a keyword query returns significantly more results than the previous cycle (>3x spike),
treat it as a trending topic. This is a proxy for trending that works within Basic tier.

**False positive filtering:** The Claude Agent SDK evaluates each matched tweet/trend for
relevance to OurNigeria's data domains. Only topics where the agent can contribute
specific budget/spending/corruption data get posted about. General political commentary
without a data angle is skipped.

### Confidence Score Definition
Reply candidates are scored on 3 dimensions (each 0-1, averaged):
- **Data relevance** (0-1): Does OurNigeria have specific data for this topic? 1.0 = exact state+year+sector match. 0.5 = state match only. 0.0 = no data.
- **Reply appropriateness** (0-1): Is a data reply useful here? 1.0 = citizen asking a question. 0.5 = citizen complaining (data adds context). 0.0 = joke/meme/sarcasm.
- **Data confidence** (0-1): How confident is the agent in the data accuracy? 1.0 = exact figures from source docs. 0.5 = aggregated/estimated. 0.0 = no source.

**Threshold:** Replies with average score < 0.6 are auto-rejected (not queued).
Replies scoring 0.6-0.8 are queued as "review." Replies scoring > 0.8 are queued as "recommended."

### Opinion Tweet Recipe
**Structure:** Single tweet (max 280 chars). No thread. No link in body.
**Voice:** Pidgin English first, with one shocking number as the hook.
**Formula:** [Emotional hook in Pidgin] + [One specific data point] + [Implicit question/outrage]
**Examples:**
- "Money wey dem budget for your pikin school don vanish — ₦1.3B budgeted for Ebonyi education, only ₦2M released. Where the money dey go?"
- "Dem talk say dem fix road for Kano. But budget show ₦47B allocated, ₦3B spent. Na so government dey 'fix' road."
**Constraints:** Must cite a specific state, year, and amount from OurNigeria data. No unsourced claims.

### Database Schema

**New Prisma models (in packages/database/prisma/schema.prisma):**

```prisma
model SocialPost {
  id            String   @id @default(uuid())
  platform      String   // 'twitter'
  postType      String   // 'thread', 'opinion_tweet', 'reply'
  externalId    String?  // Twitter tweet ID after posting
  content       String   // Full post content (JSON for threads)
  triggerTopic  String?  // What trend/keyword triggered this
  dataDomain    String?  // 'budget', 'corruption', 'faac', 'govspend'
  dataQuery     String?  // The query sent to data tools
  status        String   @default("drafted") // drafted, published, failed, rejected
  publishedAt   DateTime?
  engagementData Json?   // {likes, retweets, replies, bookmarks} — polled periodically
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  // Reply-specific fields
  inReplyToId   String?  // Twitter ID of tweet being replied to
  inReplyToText String?  // Text of original tweet
  inReplyToUser String?  // Username of original tweeter
  confidence    Float?   // 0-1 composite score (see Confidence Score Definition)
  reviewStatus  String?  // 'pending', 'approved', 'rejected', 'edited'
  reviewedBy    String?  // Admin user ID who approved/rejected
  reviewedAt    DateTime?

  @@index([platform, status])
  @@index([platform, createdAt])
  @@index([reviewStatus])
}
```

### Relevance Score vs Confidence Score
Two different scores used at different stages:
- **Relevance score** (0-1): Used by `content-selector.ts` in Phase 1 to decide whether to
  post about a topic. Measures: does OurNigeria have data relevant to this trend?
  Threshold: > 0.7 to proceed. Single dimension — data availability.
- **Confidence score** (0-1): Used in Phase 2 for reply candidates only. 3-dimension
  composite (data relevance + reply appropriateness + data confidence). See Confidence
  Score Definition section.

These are NOT the same score. Relevance gates publishing decisions. Confidence gates reply
queue prioritization.

### Daily Post Cap Enforcement
Enforced in `cron.service.ts`: before each cycle, query `SocialPost` table for
posts published today (`WHERE publishedAt >= start_of_day AND status = 'published'`).
If count >= `SOCIAL_MAX_POSTS_DAY` (default: 5), skip original post generation.
If reply queue count >= `SOCIAL_MAX_REPLIES_DAY` (default: 10), skip reply detection.
Caps are env-configurable. Logged when hit: "Daily post cap reached (5/5), skipping cycle."

### packages/content/ Context
`packages/content/` is an existing shared package in the monorepo (built in plans 28 + 30).
It contains a content generation engine with:
- **Recipes**: Declarative configs (`budget-expose.ts`, `corruption-impact.ts`, etc.)
  that define data source + prompt + format
- **Format adapters**: `twitter-thread.ts` (280-char parsing), `instagram-carousel.ts`,
  `video-script.ts`, `whatsapp-forward.ts`
- **Engine**: `engine.ts` executes recipes, `batch.ts` generates content calendars

The `thread-adapter.ts` in `apps/socials/` bridges to these existing recipes by importing
and executing them. The new `opinion-tweet.recipe.ts` is added to `packages/content/recipes/`
following the existing recipe pattern — this is a shared package, and the opinion tweet
format is useful beyond just the social agent (e.g., manual content generation).

### Error Handling & Resilience
```
METHOD/CODEPATH              | WHAT CAN GO WRONG            | RESCUE ACTION
-----------------------------|------------------------------|--------------------------------
TwitterListener#poll         | 429 rate limit               | Exponential backoff (30s/60s/120s), skip cycle
                             | 503 service unavailable      | Skip cycle, retry next interval
                             | Network timeout              | Skip cycle, log warning
                             | Invalid API credentials      | CRITICAL alert, stop polling, log error
AgentService#decide          | Claude SDK timeout (90s)     | Skip topic, log warning
                             | Claude SDK 529 overloaded    | Backoff 60s, retry 1x
                             | Malformed agent response     | Skip topic, log full response for debugging
                             | Agent hallucinates data      | Post-generation check: extract cited figures, verify each exists in tool results. If any figure not found in source data, reject post and log. This is a string-match validation (not NLP) — the agent tool results contain the source figures, and generated text must cite only those figures.
TwitterPublisher#post        | Tweet too long               | Truncate to 280, log warning
                             | Duplicate content            | Skip (Twitter API rejects dupes)
                             | API error                    | Retry 1x, then mark post as 'failed' in DB
Neo4j connection             | Connection pool exhausted    | Circuit breaker, skip cycle, alert
                             | Query timeout (5s)           | Skip topic, fall back to vector-only search
PostgreSQL connection        | Connection failed            | Service health check fails, Docker restarts
CronService#tick             | Previous cycle still running | Skip (mutex lock, one cycle at a time)
```

**Monitoring & Alerting:**
- Health endpoint: `GET /health` (Docker healthcheck, same pattern as apps/api/)
- Structured logging: Every cycle logs `{cycle_id, topics_found, posts_published, replies_queued, errors}`
- Alert conditions (log to stderr for Docker log driver → CloudWatch/Grafana):
  - 3+ consecutive poll failures → WARN
  - 0 posts published in 24 hours → WARN (agent may be stuck)
  - Post marked 'failed' → ERROR
  - Invalid API credentials → CRITICAL
- Dashboard: Post activity chart (posts/day, replies queued/approved/rejected)

| Keyword search (1 rotating group) | 1 | 72 | 2,160 | Rotating A→B→C groups |
| **Total reads (Phase 1-2)** | **1** | **72** | **~2,160** | **22% of 10K cap** |
| | | | | |
| Original posts | — | ~3 | ~90 writes/mo | |
| Approved replies | — | ~5 | ~150 writes/mo | |
| **Total writes** | | | **~240** | **0.5% of 50K cap** |

**Buffer:** 78% read budget remaining for engagement polling (Phase 3, ~1 read per
published post per day = ~90 reads/mo) or increased poll frequency during breaking events.

**Phase 3 engagement polling:** 1 read per published post per 24h cycle. At ~3 posts/day
= ~90 reads/mo. Total with Phase 3: ~2,250 reads/mo (23% of cap).

### X API Policy Compliance
- **Original posts**: Auto-published. Compliant — accounts can post their own content.
- **Replies**: NEVER auto-sent. Always queued for human approval. Compliant with X's
  prohibition on "automated replies to posts based on keyword searches."
- **Rate limits**: Well within Basic tier caps (see rate limit budget above).
- **Disclosure**: Account bio includes "AI-powered" (already in proposed bios from research).
  Individual posts are NOT labeled as bot-generated — they are data-driven content from a
  civic organization, authored by an AI tool the org operates. This is consistent with how
  media orgs use AI writing tools. If X introduces mandatory AI labeling, we comply.
- **Daily post cap**: Max 5 original posts/day + 10 queued replies/day (configurable via
  env: SOCIAL_MAX_POSTS_DAY, SOCIAL_MAX_REPLIES_DAY). Prevents runaway posting.

### Phased Delivery
**Phase 1: Foundation** (must ship first)
1. NestJS service scaffold: Dockerfile, project.json, Infisical config, health endpoint
2. Platform adapter interface + Twitter adapter: auth (OAuth 1.0a User Context for write access), post tweet, post thread, search
3. Listener: poll Search API with keyword rotation strategy (see Keyword Strategy)
4. Claude Agent SDK integration: topic-matcher + content-selector (decides what to post, what format)
5. Auto-publish pipeline: generate → post → record in SocialPost table
6. Opinion tweet recipe in packages/content/ (see Opinion Tweet Recipe spec)
7. Cron scheduler with mutex lock (one cycle at a time, skip if previous running)
8. Error handling: retry logic, circuit breakers, structured logging (see Error Handling table)

**Phase 2: Reply Intelligence**
9. Reply candidate detection: identify citizen questions/complaints about government
10. Draft reply generation with confidence scoring (see Confidence Score Definition)
11. Reply queue: SocialPost records with reviewStatus='pending', dashboard API endpoints
12. Dashboard reply queue UI: list pending replies, show original tweet + drafted reply + confidence, approve/edit/reject buttons
13. Approved reply posting: on approval, post via Twitter adapter, update SocialPost status

**Phase 3: Analytics**
14. Engagement polling: periodically read engagement metrics on published posts (uses remaining read budget)
15. Content performance dashboard: posts/day chart, engagement by type, top-performing content
16. Post-type performance tracking: which recipe types (thread vs opinion tweet) and which topics get most engagement. Stored as aggregated metrics in SocialPost.engagementData — NOT an ML system, just a reporting dashboard that humans use to adjust the keyword strategy and content mix.

### Dependency: GraphRAG (soft dependency, not a blocker)
The social agent's unique differentiator is knowledge graph traversal for cross-domain
insights. GraphRAG is built on `feature/graphdb` and should be merged before socials ships.

**With GraphRAG:** Agent queries Neo4j for multi-hop connections (governor → EFCC cases →
budget allocations → contractors). Posts are uniquely data-rich.

**Without GraphRAG (fallback):** Agent uses existing vector search tools (`budgetSearchTool`,
`corruptionSearchTool`, etc.) via direct imports. Still produces data-driven content but
limited to single-domain queries — no cross-domain graph traversal. This fallback is
fully functional and shippable.

**Implementation:** The agent service accepts an optional Neo4j connection. If `NEO4J_URI`
is not set, graph tools are excluded from the agent's tool set. No code changes needed
to switch between modes — just env var presence.

**Recommendation:** Merge GraphRAG first, then create a new branch for `apps/socials/`.
But the social agent CAN ship without it.

## Reviewer Concerns
The following issues were identified during adversarial spec review and should be resolved
during `/plan-eng-review` (engineering plan):

1. **ESM/CJS incompatibility**: `packages/content/` uses `"type": "module"` with no `exports` field. NestJS defaults to CJS. Importing recipes will fail without either configuring NestJS for ESM or adding a CJS build to `packages/content/`. Resolution: add `exports` field + dual build, or move opinion tweet recipe into `apps/socials/` directly.

2. **Hallucination check normalization**: Generated text uses human-readable figures ("₦1.3B") while source data stores raw integers (1300000000). String-match validation won't work. Resolution: implement number normalization (parse ₦/B/M/K notation to raw integers before comparison).

3. **Reply source undefined**: Phase 2 reply candidates — are they from keyword search results, @awanigeria mentions, or both? Mentions require a separate API endpoint (`GET /2/users/:id/mentions`) and separate read budget. Resolution: define in eng plan.

4. **Search API result count for trend detection**: `meta.result_count` on Basic tier is per-page (10-100), not total corpus. Volume spike detection (>3x) needs careful implementation — compare result counts at same page depth across cycles. Resolution: define algorithm in eng plan.

5. **`social_keywords` SystemSetting schema**: No value format defined. Resolution: define as JSON `{groups: [{name, keywords, domain}]}` in eng plan.

6. **Tweet too long — truncation**: Truncation at 280 chars produces gibberish. Resolution: regenerate with tighter prompt or split into thread. Fix in eng plan.

7. **Opinion tweet recipe placement**: YAGNI concern — placing in `packages/content/` (shared) vs `apps/socials/src/content/` (local). Resolution: start local, move to shared when a second consumer appears.
