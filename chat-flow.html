Step-by-Step Execution

1

Request Reception & Validation

The flow begins when the user submits a message via the Next.js frontend.

  • The request hits the NestJS backend at the POST /api/chat endpoint.
  • ChatController validates the input (e.g., checks message length ≤ 5000 chars).
  • ChatRateLimitService verifies the user hasn't exceeded their rate limit.
  • SSE Initialization: Response headers are set to text/event-stream to allow real-time streaming back to the client. A 15-second keep-alive heartbeat interval is established to prevent reverse proxies (like Cloudflare/Nginx) from dropping long-running connections.
2

Phase 1: Context Preparation

Before involving the AI, the system gathers context. This is non-idempotent and is called exactly once via ChatService.prepareChatContext.

  • Conversation Management: Retrieves an existing conversation or creates a new one, generating a title if it's new.
  • Message Persistence: Saves the user's message to the database immediately. It includes retry logic (`P2002`) to handle sequence number collisions cleanly.
  • Context Building: Retrieves up to 40 recent messages and enriches them with summaries of rich data components previously shown to the user.
  • Token Budgeting: To fit within the LLM's context window, it calculates token usage (using estimateTokens) and drops older messages if the budget is exceeded, maintaining the overarching conversation summary.
  • User Profile: Loads the user's long-term memory profile.
3

Phase 2: Intent Classification & Routing

The system determines exactly what the user is asking using a three-stage routing mechanism via mastra/router.ts.

  • Stage A (Fast Keyword Search): Checks for decisive hardcoded keywords (e.g., "budget", "EFCC", "FAAC", greetings). If a high confidence score is hit, it routes instantly without an LLM call.
  • Stage B (Cache): Checks if an exact matching prompt + context combination exists in the Redis cache.
  • Stage C (LLM Router): Invokes the routerAgent LLM to classify the query into: general, budget, corruption, govspend, faac, impact, follow_up.
  • Follow-up Handling: If the intent is "follow_up" (e.g., "What about Kano?"), it routes back to the previous specialist agent to maintain continuity.
  • Entity Extraction: Identifies states, years, sectors, and officials explicitly to feed as hints to the specialist agents.
4

Specialist Agent Execution

The request is forwarded to a targeted AI agent built on the Mastra framework.

  • Prompt Construction: Merges language directives (English or Pidgin), user memory, previous conversation summary, recent history, entity hints, and Graph Hints (if relationships are queried) into a final prompt.
  • Agent Invocation: The specialist agent (budgetAnalyst, corruptionAnalyst, faacAnalyst, etc.) takes over.
  • Autonomous Tool Usage: Agents have access to vector search databases, SQL databases, and graph search tools. They autonomously execute RAG (Retrieval-Augmented Generation) based on the user's request.
5

Streaming & Formatting (streamWithThinking)

The response is sent back to the user incrementally.

  • Thinking Steps: If the agent calls tools (e.g., querying pgvector), the tool names and internal reasoning texts are intercepted and streamed as thinking events for the UI dropdown.
  • Text Streaming: The final synthesized answer is streamed piece-by-piece to the frontend via text events.
  • Rerouting: If an agent realizes halfway through that another domain should handle the query, it outputs [REROUTE:domain]. The stream intercepts this, aborts, and restarts the flow with the correct agent (limited to 1 reroute to prevent loops).
  • Citation Alignment: Extracts sources from tool results, maps LLM citations like [1] to the correct source documents using fuzzy matching (by state, filename keywords, and Naira amounts), and scrubs orphaned citations.
6

Completion & Background Tasks

Once the stream ends, the backend finalizes the transaction and queues asynchronous background work.

  • Persistence: The final assistant response, rich content data (graphs, tables), and processing time are saved to the Message table.
  • Conversation Updates: The Conversation row is updated with the last used agent and newly discovered entities (states/years).
  • Graph Suggestions: A non-blocking call fetches related Graph entities to power follow-up chip suggestions in the UI.
  • Done Event: The done SSE event fires, passing the full rich payload, sources, and UI follow-ups to the frontend.
7

Asynchronous Housekeeping

System maintenance executes without blocking the user's response time.

  • Langfuse Observability: Logs the trace, latency score, token counts, and checks if sources/summaries were present.
  • Summarization: If the conversation grows too long, an LLM compresses older messages into a running summary string to save context window space for future turns.
  • Source Tracking: Persists SourceReference rows mapping the citations to specific documents and chunks for analytics.
  • Memory Extraction: Updates the user's cross-session profile with preferences and frequent queries.
